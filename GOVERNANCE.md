# Governance

Antaeus begins as a maintainer-led open-source project. The initial maintainers set project scope, approve public contracts and releases, and are accountable for security, compatibility, and repository stewardship.

## Decision making

Routine changes are decided through issue and pull-request discussion. Maintainers aim for reasoned consensus, but may make the final decision when consensus is not available. Decisions that materially affect architecture, security, compatibility, governance, or project scope require a written decision record before implementation.

Public contracts are changed deliberately. A merged implementation does not by itself create a compatibility guarantee; the compatibility policy and supported surface must identify that guarantee explicitly.

## Maintainer responsibilities

Maintainers are expected to:

- review contributions respectfully and in a reasonable time;
- protect users from avoidable security and compatibility risks;
- keep releases, documentation, and support claims accurate;
- disclose relevant conflicts of interest;
- enforce the Code of Conduct consistently; and
- distinguish project decisions from commercial-service decisions.

## Becoming a maintainer

Maintainership is earned through sustained, constructive contributions and demonstrated judgment in the relevant area. Existing maintainers may invite a contributor after considering technical quality, review participation, reliability, security awareness, and community conduct. As the project grows, this file will be revised to name roles, nomination rules, decision thresholds, and succession expectations.

## Project and commercial boundaries

The public project owns the reusable engine, CLI, portable contracts, evaluator extension points, conformance fixtures, examples, and release artifacts. Hosted customer operations, credentials, billing, review workflows, hosted analytics, and private production integrations are outside this repository.

Commercial employment, sponsorship, or access does not bypass the public review and compatibility process. The initial maintainer concentration is explicit; broader governance should follow demonstrated contributor participation rather than being claimed prematurely.
